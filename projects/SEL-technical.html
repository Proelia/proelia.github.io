SEL — architecture detail

Multi-agent edge architecture for offline / contested environments: specialised roles, shared state, explicit inhibition. Research-stage.

Scope: This page is for engineers and researchers. For a non-technical overview, use the plain-language dossier.

Quad-agent model

SEL separates reaction, planning, inhibition, and integration into four agent roles. Isolating these functions is intended to improve resilience versus a single unconstrained model.

ExecutorHigh-frequency telemetry (GPS/IMU/etc.); short-horizon tactical proposals
StrategistMission briefs, long-horizon planning, pattern recognition
CriticROE / legal / thermal / power constraints; proposal inhibition
SynthesizerConsensus resolution; machine-facing commands + human-readable status

Shared Thought Space (STS)

Agents observe a high-speed shared workspace (conceptual RAM-backed blackboard) rather than relying only on high-latency message passing. This enables interrupt-style inhibition: the Critic can assert a kill-bit before prohibited commands reach actuators.

Practical multi-agent loops today are exercised through related lab software (Vespera). Full hardware-bound STS and certified interrupt paths remain research maturity.

Technical posture

  • Local / quantised LLMs on edge or NPU-class hardware
  • Role separation as a first-class architectural invariant
  • Inhibition as a structural gate, not prompt-only soft advice
  • Human-in-the-loop for high-risk action classes

Domain framing (research)

  • Denied / contested RF environments where cloud stacks fail
  • Offline sensing and resilience hubs
  • Remote industrial / agricultural edge agents
  • Digital coordination agents using the same logic layer

Maturity statement

Architecture and role design are the primary artefacts. End-to-end productisation, formal certification, and fleet deployment are not claimed as shipped capability. Related open software experimentation lives in the Vespera multi-OS stack.
